# v1.13.1 — 修复 DSH profile 自更新

这是一次针对 GitHub Release 自动更新器的补丁版本。

## 修复内容

- 修复插件从 workspace `.dsh/plugins/...` 运行时，把 workspace `.dsh` 错误识别成 DSH web profile 的问题。
- 对 `link:` / `file:` 开发依赖，不再依赖插件路径猜运行目录；改为扫描 `~/.dsh/profiles/*/package.json`，匹配实际链接到当前插件 checkout 的 profile。
- 更新命令现在在真正运行插件的 DSH profile 中执行，使 `link:` 开发依赖迁移为固定 GitHub Release tarball 依赖。
- 更新完成后增加强制验证：只有 profile 依赖已脱离 `link:/file:`，并且 `node_modules/dsh-usage-plugin-v2/package.json` 的版本与目标 Release 完全一致时，才显示安装成功。
- 如果无法唯一确认运行 profile，自动更新会停止并提示手动处理，不再修改无关 workspace。

## 解决的问题

此前可能出现：界面提示“安装成功”，但 `pnpm add` 实际修改的是 workspace 层 `.dsh/package.json`，而 DSH web profile 仍通过 `link:` 加载旧 git checkout。重启后版本因此没有变化。

v1.13.1 将运行 profile 作为更新目标，并对实际安装结果做版本校验，以避免这种“假成功”。
